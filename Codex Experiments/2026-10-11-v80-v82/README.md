# QuantMatmulReluQuant 离线连续实验：v80–v82

日期：2026-10-11。当前已验证基线是队友仓库 `Carl Memory/推荐版本/kernel.asc`（v76/v78 同字节），SHA-256 `4bc693a338ae478445fb7aed2d95cae30c3d6bf33fe7fcf5b5a27d4048fdb0d7`。用户报告该版本成绩为 24.7，但原始平台 15 点记录尚待提供。三个新版本均为**未经编译、未经 NPU 运行、未经精度和性能测试的源码实验**。不要将它们称为提分版，不要覆盖已验证基线。

| 版本 | 相对上一版的单项改动 | 源码 SHA-256 | 预期与风险 |
|---|---|---|---|
| v80 | 移除一般向量路径第一遍结束时的 `rowMaxLocal = max(rowMaxLocal, 0)` 及其屏障。该缓冲区以 0 初始化，仅在 `tileMax > oldMax` 时更新。 | `c6aa4372b4dec699305d168e6af0142732546c2d2f6e86644b608264206c4f2d` | 少一次向量指令和屏障；需要设备确认编译与同步语义。 |
| v81 | 在 v80 上，移除第二遍针对零最大值行的 `Duplicate` 分支、屏障及不再使用的最大值预取。第二遍复用同样的输入和乘法，随后已有 `Maxs` 实现 ReLU。 | `a9f137549d9ff4dc7348c9fc9d56751f9fd676a09de09d845de6bff22b80bd1a` | 减少每组标量读取、分支和屏障；若两遍的浮点行为不同，需以 15 点精度结果否决。 |
| v82 | 在 v81 上，tiny direct 路径仅在 `N<32` 时清零激活缓冲。该路径门控 `N<=32`，当 `N=32` 时每行的 32 个 lane 均会被写入。 | `849358aa5267ea24b600d6cb458db72abb2e282d6495ecd7b92de618ef062e37` | 只可能改善 tiny 且 `N=32` 的用例；需要设备验证局部缓冲和屏障时序。 |

三个版本是累积链 `v76 → v80 → v81 → v82`，不是三个都经过上机验证的“改进版”。此前的 v79 是从 v76 单独派生的另一项 tiny staging 实验，未混入这条链。所有改动均位于 Ascend C device 路径，不引入 CPU 算结果、外部数据依赖或针对评测输入的硬编码。

本轮按用户要求**暂不运行测试**。仅做了源码差异人工复核、版本 SHA-256 记录以及确认队友仓库未被修改；这些检查不能替代 CANN 编译、15/15 精度或真实榜单分数。之后有设备时先确认同一评分窗口的 v76 基线，再按 v80、v81、v82 顺序逐版测；任一版编译失败或任一点精度不通过，立即停止累积链并回退。每次保存任务号、源码 SHA、15 点耗时和平台分数。只有重复实测稳定提升后，才同步到队友 GitHub 仓库。
