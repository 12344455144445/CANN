# 10.13 行驻留框架设计与实验

使用用户确认的 v124 原样源码为基线，SHA256 `4010bfbbb0f4d1be969556db956cebad2de65b7784bb5a9da55b57ea25338574`。Sheldon 10.13 am 属于新增研究参考，不能在未取得并核验源码时把它解释成已实现或已设备通过的版本。

基线正常 Vector 路径先为整个 AIV 行区间扫描全部 N 块，获得行最大值并修复输出尺度，再重新读取全部 C、重新 Cast INT32 到 FP32、再次进行两个缩放乘法后量化。这保证了任意宽 N 的泛化，但完整行放得进 UB 时，第二遍 GM 读取和反量化可以由保留原 FP32 结果替代。两次浮点乘法的顺序、原精确尺度除法修复、量化除法、近半值精修与 ODD/RINT 转换不变。

## 与旧实验的实质区别

v70 已尝试逐 1–4 行一遍路径，但逐批使用标量 uint64 除以 127 求尺度。其标量开销不能用于否定统一原向量修复的一遍框架，也不能重做后宣称为新结构。

v104 只在整个局部 rows 小于旧 rowBatchLimit（1–4 行）时保留一批激活，覆盖很窄。v134 按整个矩阵实际容量判断，最多保留 192 行；v138 则允许任意局部 rows，逐容量批处理，最多 256 行。

v116 已尝试激活与 quotient 交换 UB bank，单独试验收益不成立。v138 将此存储技巧作为一遍框架的组成部分，在精确尺度修复时借用已消费的 INT32 bank，避免把激活复制后又读取，不宣称 bank 交换本身有已验证增益。

## v138 的生命周期和资源预算

设批行数 B = min(rows, floor(8192/N))，T = align64(B×N)，R = align64(B)。新 helper 在原 fallback 的 TPipe 创建之前分流，执行时只存在一个分支的显式 UB 分配。

显式 UB 字节为：

```text
17 × T + 4 × N + 12 × R + 128 + align32(T/8)
```

其中 17×T 为四个独立 FP32 容量 bank 和 INT8 输出；4×N 为只读列尺度；12×R 为行输入尺度、行最大值和输出尺度；128 B 为四个按 8-float 间隔的 scalar reduction 输出；末项为位掩码。

在全部 N=32,64,…,8192 和所测试行数下，显式峰值为 173952 B。计入 Select API 的 8192 B 保守预留，总计 182144 B，小于 A3 的 196608 B。没有使用 CANN 950 MicroAPI 或任何新 API。N 为 32 倍数，使多行扁平 DMA 和每一行 FP32/INT8 的 UB、GM 基址均对齐。T 和 R 按 64 元素对齐，掩码按 32 B 对齐；量化比较可能访问的填充尾元素会预先初始化。Div 的 fullRepeats 最多 128，符合现有 uint8 参数范围。

生命周期依次为：

1. 每批只载入一次整数 C，转换到独立 FP32 bank，并先乘行尺度、再乘列尺度。
2. 所有 INT32 读完后，其 bank 才可被尺度修复 scratch 覆盖；保留激活的 FP32 bank 不参与尺度 scratch。
3. 批内最大值完成后，原 QmqCorrectDiv 统一求尺度，处理零行并缓存有效尺度。输出尺度 bank 保留到量化和 GM 写出完成。
4. 原激活执行 ReLU；先前 INT32 bank 改为 quotient。量化近半值精修仍读取未覆盖的原激活和已确认尺度。
5. CAST_ODD 到 HALF、CAST_RINT 到 INT8；写出本批输出，释放本批队列 bank。只读列尺度维持到所有批次结束。
