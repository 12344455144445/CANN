## §0 一句话定义

在 **Atlas A3（910C，arch `dav-2201`）** 上实现算子 `QuantMatmulReluQuant`：
**INT8 matmul + ReLU + 动态逐 token 量化**（融合成单个 kernel）。

## §1 题目规格（官方契约，**不可协商**）

| 项 | 规定 |
|---|---|
| 形状范围 | `M, N, K ≥ 1`（**只有下界，没有上界、没有对齐要求**）|
| `x1` | `(M, K)`，**不转置** |
| `x2` | `(N, K)`，**固定已转置** |

| 舍入 | **`rint`（就近偶数 ties-to-even）** 后 clamp 到 `[-128, 127]` |
| 退化行 | `rowMax == 0` ⇒ 该行 `yScale = 1.0f` 且 **该行 `y` 全为 0** |
| 空 Tensor | **不支持**；仅支持连续内存 |
| 判分容差 | `y` 走 `np.array_equal`，**tol = 0 ⇒ 逐元素位级全等**；仅 `yScale` 容 `0.01% × 1e-4` ⇒ **必须给出位级等价证明** |

## §2 评分公式 —— **总分 ≠ 总耗时**（最重要的认知）

```
S_i  = 100                                , 若 t_i ≤ T_i   （封顶 100，做快了没有额外奖励）
     = 100 / (1 + log₁.₅(t_i / T_i))      , 否则
总分 = (1/15) × Σ S_i        （15 个测试点等权平均）
```

由此推出三条必须刻进脑子的推论：

1. **只与 `t_i / T_i` 有关**，与绝对耗时无关。
2. **单点弹性 `ΔS = 2.4663e-4 × S²`（每 1%）** ⇒ 分越低、提速越值钱。
3. **边际价值 `dS/dt ∝ S² / t`** ⇒ **小 `t` 的点每 1 µs 值钱得多**。
   **按 `dS/dt`（分/µs）排序**：点4 `.2318`｜点5 `.2294`｜点6 `.1792`｜点9 `.1703`｜点7 `.1689`｜点10 `.1533`｜点12 `.1313`｜点14 `.1154`｜点11 `.1141`｜点15 `.1098`｜点13 `.1097`｜点3 `.1082`｜点1 `.0933`｜点2 `.0858`｜点8 `.0738`。
   ⇒ **一个只在小点上生效的优化，可能比全局提速 20% 更值钱。**

### ★ `T` 是移动靶（E114）

平台「最优用时」`T` **会随全局最优改善而下降** —— 观测到：点 3 从 `2.60 → 2.50`（多轮）、点 10 从 `38.17 → 36.46 → 36.30`。
⇒ **所有历史分数的绝对值不可比**，只有**同一时间窗口内的相对变化**可信（E104）。
⇒ `ref/score_v48_live.py` 里的 `T` 常量**必须注明「截至某次提交」**。

### ★ 核类型红线（E39）—— **唯一能跑的形态**

> **单核 `__global__ __mix__(1,2)` 裸声明、零类型宏、单次 launch、形参表 13 项。**

### ★ 失败签名（E40 / E41）

- `用时 -` + 100% + 全点败 = **启动失败**。

### ★ 评测脚手架真相源（`02_code/pkg_snapshot/main.asc`）

```
aclInit → aclrtSetDevice(0) → aclrtGetDeviceInfo(ACL_DEV_ATTR_CUBE_CORE_NUM)
→ aclrtCreateStream → 【一次 run_kernel(...)】 → aclrtSynchronizeStreamWithTimeout(3000)

```

**★★ 关键推论**：`main()` **每个进程只调一次 `run_kernel`** ⇒ **任何 host 侧的「缓存」结构性不会命中**。
⇒ **host 侧优化这条路不是「收益小」，而是「无效」**（详见 §5 禁做清单 + E116）。

## §4 精度红线（**逐字节不可改** —— 指【函数实现体】）

| 函数 | 内容 | 为什么不能动 |
|---|---|---|
| `QmqQuantizeNearHalf` | 用**整数尾数比较**精确复现 `rint` 的 tie-breaking | 判据比 `Compares` 的 `2e-05` 严约 **1000 倍** |
| `QmqDiv` | 除法 | 位级精度 |
| `QmqCorrectDiv` | 修正除法 | 位级精度 |

> 注意：**调用点参数顺序不是红线**（可以改）；**函数实现体是红线**（一个字节都不能改）。
> `ref/precision_guard.py` 会给出三红线的 sha 指纹 + 数值路径函数是否改动 —— **这是权威口径**。

**`QmqQuantizeNearHalf` 内部逻辑（供理解，不要照抄修改）**：
`lowerInteger = (int)approximate` → `distance = |bits(approximate) − bits(lowerInteger+0.5)|` → `distance > 2U ⇒ return -1`
→ `thresholdMantissa = 2*halfMantissa + ((lowerInteger & 1) == 0 ? +1 : -1)`
→ `shift = activationExponent − scaleExponent − thresholdExponent`
→ `return lowerInteger + (((lowerInteger & 1) == 0) ? above : (above || equal))`

## §5 ★★「不要做什么」清单（血泪换来的，每条都有实测背书）

| ⛔ 禁止 | 编号 | 实测证据 |
|---|---|---|
| **行体（含尾部三级 `Cast` 中转区）的任何微扰** | **E112 / E115** | v41 +1.65%｜v42 **+17.85%**｜v43 +17.61%｜v46 **+20.13%**｜v47 +0.7%｜v48 **+1.87%（−0.5111 分）** ⇒ **六连败、零胜** |

| **host 侧任何优化**（workspace 缓存 / tiling 缓存） | **E116** | v21：`PATCH-H1+H2` 只值 0.41%（噪声内）；且 `main.asc` 每进程只调一次 ⇒ **结构性无效** |
| **AIC 入口旁路**（`TPipe`/`Matmul` 构造/`REGIST_MATMUL_OBJ` 上做文章） | **E97** | v40 实测收益 ≈ 0 |

| **多行块 DMA** | — | UB 装不下 |
| **B5（把残差判据从 `|f−0.5|` 改成 `|d−rint(d)|`）** | — | **数学否证**：二者互补而非恒等；且预筛 `ReduceMin` 判据**方向反转** ⇒ 扫描被跳过 ⇒ **输出错误** |
| **再用 A / B2 / C 三组改动** | E115 | A（删行体恒等 `Maxs`）省 27.54 µs 但 **−0.1523 分**；B2 掉分；C = **+748.26 µs 的元凶** |
| 依赖 `v41/v42/v43/v46/v47/v48` 的任何代码 | — | 全部永久弃用 |

### ★ 为什么「行体微扰」必然有害（机制）

Pass-2 行体是**串行依赖链**：**17 条向量指令 + 1 条 UB→UB `DataCopy` + 1 条 `DataCopyPad`**，首尾相接（E108）。
⇒ 删 1 条 ≈ −5.3% **行体**时间 ≈ **−0.74% 总耗时 ≈ +0.09 分**（**落在噪声带以下**）。
⇒ **单条指令级改动永远测不出来。收益必须结构级**（≥2~3 条同时动，或两行交织，或小 N 多行打包）。
⇒ 而**结构级改动**又必须跨过 E112 的「扫描区悬崖」。⇒ 这就是为什么**主攻方向只能是「行间双缓冲」**（见 `04_next/NEXT_STEPS.md`）。

## §7 硬约束速查（常量与形状）

```
kVectorTileN        = 6144          kVectorTileRows     = 1024
kFloatBlock         = 8             kHalfScreenTolerance= 2e-05f
kCubeToVectorFlag   = 8             kCubeToVectorFlagB  = 9
kMaxMBlocksPerGroup = 2U            kPrefetchSpan       = 64
kQmqTinyMaxM = 96   kQmqTinyMaxN = 32   kQmqTinyMaxK = 64   kQmqTinyMaxNK = 256
UB(AIV) 上限 = 196,608 B（192 KB）   当前占用 = 170,784 B（余 25.2 KB）
```

**tiny 门控 `QmqTinyShape`**：`m>0 && n>0 && k>0 && m≤96 && n≤32 && k≤64 && (n*k)≤256`。**点 1 = `(4,8,16)` 必命中**。

**`m` 侧形状分区（可靠）**：
点 **2 → `m≤8`**｜点 **1/3/5/7/11 → `m∈[9,192]`**｜点 **4/14/15 → `m∈(192,384]`**｜点 **6/8/9/10/12/13 → `m>720`**（`(384,720]` 是空区）。

**`currentN` 侧分区（E113 存疑，需重标定）**：
`N < 2048` = 点 8/11/12/13/14/15｜`N ≥ 2048` = 点 4/5/6/7/9/10。

**时序模型**：
```
singleCoreM = tileM ;  activeAivCount = ceil(m / singleCoreM)
mBlocksPerGroup = clamp(ceil(activeAivCount / usableCoreNum), 1, 2)
activeGroupCount = ceil(activeAivCount / mBlocksPerGroup)
launch <<<activeGroupCount, 0, stream>>>(...)
```
**device 侧**：`mBlocksPerGroup ≥ 2` 才有 cube/vector 重叠；`= 1` 完全串行（E88）。

**调用次数上界（重要）**：`blockM = tileM`（4 或 16）⇒ `halfM ≤ 8` ⇒ **`quant_matmul_relu_quant_vector` 每核被调用 ≤2 次、每次 `rows ≤ 8`**；`rowOffset` 循环**只跑 1 次**。

**同步 API**：`<2, PIPE_FIX>` 只在**一个 group 内**有效；`SyncAll<false>()` = 全核栅栏（占 FFTS flag **11~14**）；flagId 范围 **0~10**；同一 flagId **最多设 15 次**；**禁连续设置**。
