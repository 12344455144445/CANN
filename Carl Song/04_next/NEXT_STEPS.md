### v49 是什么（4 处改动，全在行体之外）

> **极小形状免除跨核握手**。让 AIC 在 tiny 形状下不再发跨核 flag、AIV 也不再等它。

| # | 位置 | 改动 |
|---|---|---|
| **H1** | AIC 三个提前返回分支（入参非法 / tiny 旁路 / 无 mBlock） | `QmqCubeSignalAllFlags(mBlocksPerGroup)` 包进 `if (!QmqTinyShape(m,n,k))`；tiny 旁路那处直接删掉置位 |
| **H2** | AIV 的 `CrossCoreWaitFlag<2,PIPE_FIX>(8/9)` | 包进 `if (!tinyShape)` |
| **H3** | AIV | `const bool tinyShape = QmqTinyShape(m,n,k);`（纯 CSE，避免重复求值）|

### 为什么等价（三条论证）

1. **极小形状下 AIV 对 AIC 无数据依赖**：此时 C 由本 AIV 自算（`QmqComputeTinyC`），`y` / `yScale` 也由本 AIV 写。
2. **两侧门控是同一纯函数 + 同一组 `m/n/k`** ⇒ **Set 与 Wait 同时为 0，flag 计数器零变化**（配平表覆盖五种情形，不存在单边收发）。
3. **零风险证据**：`precision_guard` ⇒ `quant_matmul_relu_quant_vector` **整函数逐字节未改**；生成器 A10b 证明**行体 + 扫描区逐字节一致**；`PipeBarrier<PIPE_V>` 47→47、`Compares(` 1→1、`ReduceMin(` 1→1、`if (currentN >= 2048U)` 1→1。

**目标**：把 `O ≈ 10.4 µs` 里的「AIV 前置段」继续压缩。

### 已排除的候选（E116，不要再试）

| 候选 | 实测 | 结论 |
|---|---|---|
| host 侧（workspace / tiling 缓存）| v21：`PATCH-H1+H2` = **0.41%**（噪声内）；`main.asc` 每进程只调一次 ⇒ 缓存**结构性不会命中** | ⛔ **永久关闭** |

| `QmqComputeTinyC` 全长 | v40 旁证：**仅 +0.30 µs** | ⛔ 关闭 |

⇒ **剩余唯一未标定 = AIV 的 `CrossCoreWaitFlag(8/9)` 阻塞**（v49 正在标定它）。

### 若 v49 兑现，下一步方向

**把 `C` 的 GM 往返改成 UB 直通**（`analysis/48` §5.4 note 2）：
当前 tiny 路径的 C 是先写 GM workspace、再由 AIV 从 GM 读回 ⇒ 若能在**同核 UB 内直接交付**，可再砍一段。
⚠️ 已知风险：`analysis/48` §5.4 记录了两个实施前未知 —— ① `Cast` 的合法源类型；② **同核 GM 写→读可见性**。动前必须先解决这两个。

**时序论证（为什么是这里）**：
AIV 到达 `CrossCoreWaitFlag` 只需 `InitSocState` + `GetBlockIdx`×2 + `GetSubBlockIdx` + **4 条标量运算**
（15 次 `InitBuffer` 全在 Wait **之后**，在 `quant_matmul_relu_quant_vector` 内）；
而 AIC 要到 `CrossCoreSetFlag<2,PIPE_FIX>` 需走「入口 + `SetSysWorkspace` + 5 项入参校验 + `QmqTinyShape` 判定 + 置位 + flag 传播」。
**反证**：若等待为 0，则 v40 拿掉 AIC 入口整段在点 1 上就该有收益 —— 实测为 0
⇒ 两者**只能同时成立于**「AIC 入口本身便宜、但 AIV 仍在等它跑完入口」。

## §3 若 v49 打平 ⇒ 主攻 E100「行间双缓冲」（**长期主线**）

### 问题（E100 = 全题唯一的大头）

**同一 `m` 分区内，`N < 2048` 的点效率低 1.5~3.4×**。剥掉 `O = 10.5` 后的比值：

| `m` 分区 | 低效点 | 高效点 |
|---|---|---|
| `m ≤ 192` | 点5 (1.17) / 点7 (2.55) | **点11 (4.27)** |
| `(192,384]` | 点4 (1.31) | **点14 (4.44) / 点15 (4.58)** |
| `> 720` | 点6 (2.11) / 点9 (2.68) / 点10 (2.99) | **点8 (7.06) / 点12 (3.74) / 点13 (4.48)** |

**机制**：行体的**固定延迟被 `N` 摊薄** ⇒ `N` 小则固定开销占比爆炸。
⇒ **出路只有两条：缩短链（撞 E112 悬崖）或 2 行交织（本文推荐）。**

### 设计（`analysis/57` §七）

**原理**：当前 `fp32Buffer` / `halfBuffer` / `reduceBuffer` / `correctionMaskBuffer` 在**行之间被复用**
⇒ 相邻两行的行体链之间存在 **WAR 依赖** ⇒ 必须串行 ⇒ 每行的**固定延迟**全额暴露在关键路径上。
**若给这四个缓冲各加一份**并让相邻两行轮流使用，两条独立链即可在向量流水里重叠。

**★ UB 预算（必须先改 `kVectorTileN`）**：

| `kVectorTileN` | 当前占用 | 双份后 | 可行 |
|---|---|---|---|
| 6144（现状）| 170,784 B | 170,784 + 74,496 = **245,280 B** | ❌ 超 196,608 B 上限 |
| **4096** | 103,072 B | 103,072 + 49,664 = **152,736 B** | ✅ 余 43.8 KB |

⇒ **必须先把 `kVectorTileN` 从 6144 降到 4096**。
⚠️ 代价：`N > 4096` 的点（点 6 `N=6144`、点 13 `N=4097`）会多一次 `nOffset` 循环
⇒ **必须自带形状对照验证**（点 5 `N=4096`、点 12 `N=4096` 不变）。

**理论收益**：若行体确为**延迟受限**，两行交织可把「每行延迟」隐藏为「每行吞吐」
⇒ 行体时间 **−30~50%** ⇒ 按 E100 比值表可对应 **+1.5 ~ +2.5 分**。

**★★ 这是「提到 25 分」唯一现实的主攻方向**（单条指令 ≈ −0.74% 总耗时 ≈ +0.09 分，远不够）。

### 建议的实施顺序（单变量，逐步）

1. **先只改 `kVectorTileN` 6144 → 4096**（不加第二份缓冲），单独测一版 ⇒ 标定 `nOffset` 多跑一次的代价。
2. **再加一份 `fp32Buffer` + `halfBuffer`**，测 ⇒ 看两条链能否重叠。
3. **最后加 `reduceBuffer` + `correctionMaskBuffer`**，测。
   ⇒ 每一步都要**自带逐点对照**，且**预登记判读表**（照抄 v49 的格式）。

## §5 工作纪律（**必须遵守，否则会重蹈覆辙**）

1. **单变量**：一次只改一处（或一组强相关的），并**自带形状对照**。
2. **预登记判读表**：测之前把「什么算兑现 / 打平 / 有害」写死在 `SUBMIT.md`（照抄 `02_code/v49_SUBMIT.md` §四的格式）。
3. **逐点分组符号**：判改动好坏**看逐点 `Δ%` 的符号分布**，不要只看总耗时
   （v47/v48 的模式：`N ≥ 2048` 的 6 点全线为负 ⇒ 说明动到了与 `N` 强耦合的区域）。
4. **每次改动给替换指令**：明确告诉用户「把哪个文件替换到工程包的哪个位置」。
5. **改前跑自检**：
   ```bash
   PY=<你的 python>
   $PY 05_tools/selfcheck_all.py --cand 02_code/candidate_v49.asc --base 02_code/baseline_v45.asc
   $PY 05_tools/precision_guard.py --baseline 02_code/baseline_v45.asc --candidate <候选>
   $PY 05_tools/livecode_diff.py --a 02_code/baseline_v45.asc --b <候选>   # 判活代码归属（唯一可信口径）
   ```
6. **写生成器，不要手改 `kernel.asc`**：参考 `02_code/make_v49.py`（骨架 + 断言 A1~A12）。
   - **核心断言**：A10 精度红线三函数**定义体**逐字节不变；A10b 行体 + 扫描区逐字节一致；A11 逆变换能逐字节还原基线；A12 活代码差集白名单。
   - ⚠️ **坑**：断言计数的文本**必须先剔除注释行**（新横幅里的 `CrossCoreWaitFlag` / `QmqTinyShape` 字样会污染计数 —— `make_v49.py` 里的 `code_only()` 就是干这个的）。
7. **每次测完记录**：错误点 + 下轮方向（写入 `03_issues/` 同名日志与 `LEDGER.md` 新编号）。
