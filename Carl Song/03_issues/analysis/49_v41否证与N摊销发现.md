## 三、★★★ E100 —— 本轮真正的产出

**定义「不含 O 比值」= `(t − O) / T`，`O = 10.5 µs`。**
理由：直接看 `t/T` 会把「纯固定开销」混进来 —— 点 2 的 `t/T = 6.09` 里 **90% 是 O**
（`t = 10.78`，`O = 10.5`）。剥掉 O 之后才看得见**真实计算效率**。

| m 分区 | `N ≥ 2048` | `N < 2048` | 倍数 |
|---|---|---|---|
| `m ≤ 192` | 点 5 (1.17)、点 7 (2.55) | **点 11 (4.27)** | 1.7~3.6× |
| `(192, 384]` | 点 4 (1.31) | **点 14 (4.44)、点 15 (4.58)** | 3.4× |
| `> 720` | 点 6 (2.11)、点 9 (2.68)、点 10 (2.99) | **点 8 (7.06)、点 12 (3.74)、点 13 (4.48)** | 1.5~3.3× |

**⇒ 三个 m 分区内全部成立 ⇒ 与 `m` 无关，由 `N` 决定。**
**⇒ 例外**：点 1/2/3 的比值只有 0.16~0.40 —— 它们 `N` 也小，但 `m` 更小、`T` 也小，
属**纯 O 支配**，这条定律不适用（这也解释了为什么它们的 `t/T` 看着很难看却无处可动）。

### 3.1 机制（已核实为硬数字）

`ref/count_v39_ops.py` 对 v39 源码逐段计数：

```
Pass-2 行体(含 if 两分支): 行 745~831 向量/搬运指令 = 19  PipeBarrier = 19
段①   rowMax<=0 fixup      : 行 670~674  向量/搬运指令 =  0  PipeBarrier =  0
段②   yScale 拷贝          : 行 678~680  向量/搬运指令 =  0  PipeBarrier =  0
全文件 PipeBarrier = 48
```

⇒ **Pass-2 的内层行循环里，每行要下发 19 条向量/搬运指令，每条后面紧跟一条
`PipeBarrier<PIPE_V>`；这 19 条 barrier 占全文件 48 条的 40%。**
指令序列（`rowMaxPrefetch[row] > 0` 分支）：

```
Cast(RINT) → Muls → Mul → Maxs                 ← 4 条（无条件）
  ↓ 分支内 8 条
DataCopy(保 x) → Duplicate(scale) → QmqDiv → Cast(FLOOR) → Cast → Adds(0.5) → Sub → Abs
  ↓ 汇合后 5 条
Maxs → Mins(127) → Cast(RINT) → Cast(fp16) → Cast(RINT)
  ↓ （hasNearHalf 时再加 Compare + 掩码扫描）
```

这 19 条是**每行一份的固定开销**，被 `N` 摊薄 ⇒
`t/T ≈ [C1/(N·k) + C2/k] / c` ⇒ **`N` 越小，比值越大** —— 与上表完全一致。

### 3.2 为什么这条定律值钱

评分里 `t/T` 是唯一的自变量，而**每行固定开销不随 `N` 增**。
⇒ 只要把 `C2` 压下去，**`N < 2048` 的 6 个点会一起往下走**，而这 6 个点
恰好包含全 15 点里 `t/T` 最差的点 8（7.73）。**这是唯一一条能同时动到多点、且不需要
结构性重写的大杠杆。**

## 七、v42 候选池（按「证据强度 × 风险」排序）

### A. ~~Pass-2 行体去 `DataCopy`~~ —— **★ 本节已自我否证，作废（见 E103）**

> ⚠️ **本小节的方案是错的，保留在此仅作教训记录。**
> 我当时的论证漏了一个消费者：`QmqQuantizeNearHalf(activationLocal.GetValue(lane), scaleValue,
> fp32Local.GetValue(lane))`（v40 行 982~984）**需要 `x`**，
> 所以 `activationLocal` **不是死缓冲**，`DataCopy(activationLocal, fp32Local)` 是
> 「同时持有 x 与 q」的必要手段。
> 「把 q 写进 `activationLocal`、`x` 留在 `fp32Local`」的替代方案也不行：那样尾部的
> `Cast(inputLocal, fp32Local, CAST_RINT)` 会变成**就地 Cast**（`inputLocal` 与
> `activationLocal` 同址），在无法本地编译验证的前提下风险不可接受（E19）。

**⇒ 已替换为**下面真正落地的 v42 三处改动（见 `records/experiments/v42-rowbody/`）。

### A′. 段① + 段② 合并（低风险、**投影 0.1~0.2 分**）—— ★ 已并入 v42

```cpp
// 段①（行 670~674）：2 次 UB 往返 / 行
for (row) { if (rowMaxLocal.GetValue(row) <= 0.0f) rowScaleLocal.SetValue(row, 1.0f); }
// 段②（行 678~680）：2 次 UB 往返 / 行
for (row) { yScaleLocal.SetValue(row, rowScaleLocal.GetValue(row)); }
```

合并为一个循环（2 读 1 写 / 行）：

```cpp
for (row) {
    const float mx = rowMaxLocal.GetValue(row);
    yScaleLocal.SetValue(row, (mx > 0.0f) ? rowScaleLocal.GetValue(row) : 1.0f);
}
```

**逐位等价**：两个循环都没有向量指令、没有跨行依赖，只是标量读写；
合并后每个 `row` 写进 `yScaleLocal` 的值与合并前**完全相同**（`rowMax<=0 ⇒ 1.0f`，
否则 `rowScale`）。⚠️ 前提：段①里对 `rowScaleLocal` 的写**不再被任何别处读**
（需核对；若 `rowScaleLocal` 只在段②被读，则可合并）。
⇒ 省 **1 次 UB 标量往返/行**。**投影 +0.1 ~ +0.2 分。**

### B. Pass-2 行体「整块化」（**头寸最大，风险最大**）

把 `groupRows` 行的量化做成**一次**向量操作，而不是 `groupRows` 次：

- 前提：`groupRows × alignedN` 在 UB 里连续（`workspaceGm[(rowStart+row)*n + nOffset]`，
  行距 = `n`；当 `alignedN == n` 且 `n ≤ kVectorTileN` 时成立）。
- 代价：需要一个 `groupRows × alignedN` 的 fp32 中间张量 + 一个同尺寸的 **per-row 广播 scale 向量**
  （由 `rowScalePrefetch[]` 一次构造，`groupRows` 次 `Duplicate` 等价但**只付一次 issue 开销**）。
- **UB 预算**：`groupRows × alignedN × 4 B × 2`（数据 + scale）。
  点 8：`8 × 2048 × 4 × 2 = 128 KB`，UB 现余 25.2 KB ⇒ **装不下**；
  必须先按形状门控（只在 `groupRows × alignedN` 小到能塞进余量时启用），
  且要论证「门控不命中 = 逐字节等于基线」。
- **收益上界**：把 19 条指令的 issue 开销从 `groupRows` 次摊成 1 次 ⇒ 直接砍 `C2`。
  **这是唯一能把比值压到 3.0 以下的方案。**
- **门槛**：必须先在纸上做完 UB 预算 + 逐位等价证明，**再**写代码（E20：先证收益 ≠ 0 再写代码）。

### C. `O` 路线（理论最大，但 E19 不可本地验证）

`O ≈ 10.5 µs`，兑现表：`O → 8.0` ⇒ 24.469（+1.161）｜**`O → 6.89` ⇒ 25.0（临界）**｜
`O → 6.0` ⇒ 25.874（+2.567）。E97 已把 AIC 侧整段排除 ⇒ 只剩 AIV 侧的
`TPipe` + 12×`InitBuffer`，以及 `InitSocState`/launch。**需要一个能本地验证不了的实验。**

### D. 掩码扫描批量预取（**目前证据不足，降级为观察项**）

`for (maskGroup < compareCount/64U) { candidateMask.GetValue(maskGroup); … }`，
N = 2047 时 32 次/行。v41 用 `ReduceMin` 换它反而更慢（E101）——
**要么扫描便宜，要么 `ReduceMin` 太贵**。在没区分这两者之前，不要再动它（E102）。
