## §4 · v34：只切 AIV 的行（`records/experiments/v34-aivsplit/`）

### 4.1 定位：这是一次**测量**，不是一次"大改"

`cube 75.4% / AIV 24.6%` 这个比例**只有一处反推来源**（v17b 的 0.8769）。
而 §5 那条活口是一次**大改**（要动 vector 段的读取布局）。

⇒ 在投入之前，先用一个**便宜、不可能错**的实验把这个比例量出来。

**v34 就是这个测量**：cube 逐字节回到 v20，只把 AIV 的行区间
从「每 group 2 子核分 16 行」改成「48 子核平均分 m 行」。

* 变快 ⇒ `AIV ≈ 24.6%` 成立 ⇒ 放心投 §5；
* 无变化 ⇒ **AIV 段不按行数伸缩** ⇒ §5 也必须重新论证 ⇒ **省下一次大改的代价**。

### 4.2 设计（单一变量：谁来做行划分）

| 位置 | v34 |
|---|---|
| `quant_matmul_relu_quant_cube` | **v20 原文 83 行**（形参表去掉 `nSplitCount`） |
| host tiling 段 | **删掉全部重建 ⇒ v20 原文**（`tiling 调用 12 行` 逐行一致） |
| host 闸门 | `splitRows < plainRows` 时 `nSplitCount = usableCoreNum` |
| device AIV 段 | 模式 0 会合 → `sliceStep = ceil(m/48)` 全局行区间等分；不切分时走 v20 原文 36 行 |

**闸门参数无关（E30）**：两侧分别是 `ceil(singleCoreM/2)` 与 `ceil(m/(2*usableCoreNum))`

自动排除：`m ∈ [337,384]`（两边同为 8 行，零收益）、`m > 384`（perGroup=2）、`m ≤ 2`。

## §5 · ★★★ 25 分的唯一活口：「每窗口紧凑布局 + AIV 分段读取」

### 5.1 为什么它没被证伪

**v29 / v30 / v33 三次实验，cube 每个 group 做的都是"整 N"的工作量**
（写出宽度恒为 n）。所以**「把每 group 的 cube N 域真的缩到 windowN」这件事，
从来没有被实验过** —— 三次失败的是"怎么让 N 域变窄"，不是"变窄后有没有收益"。

### 5.2 机制：`orgN` 同时决定"范围"与"步长"

`SetOrgShape(orgM, orgN, orgKa, orgKb)` 的官方语义是**给出 A/B/C 的原始形状与 stride**
（`records/experiments/v30-nfix/SUBMIT.md` §2 已论证）。因此把它改成
`SetOrgShape(m, windowN, k, k)` 会**同时**发生两件事：

| 量 | 变化 |
|---|---|
| 该 group 计算的列数 | n → **windowN** |
| C 的行步长 | n → **windowN**（★ 这就是前三次留 `orgN = n` 的原因：为了保行主序） |

⇒ **必须同时把 workspace 改成"窗口主序"**，AIV 再**分段读**回来。

### 5.3 布局设计（窗口主序）

```
window s 的整列块 = workspace[s * (m * windowN) + r * windowN]   , r ∈ [0, m)
cube group (mBlock j, window s) 写：
    matmulObj.SetOrgShape(m, windowN, k, k);
    matmulObj.SetTail(currentM, windowN);
    matmulObj.SetTensorA(x1Gm[mOffset * k], false);
    matmulObj.SetTensorB(x2Gm[s * windowN * k], true);
    matmulObj.IterateAll(workspaceGm[s * m * windowN + mOffset * windowN]);
```

* 每个输出元素仍由**唯一**一个 group 用**同一条 INT32 累加路径**算出
  ⇒ 数值与"整 N 一次算完"**逐字节相同**（整数加法的结合律 + 同一个 mmad 序列）；
* 窗口两两不交、并集为整行；
* **`windowN` 与 `m * windowN` 均为 `windowN` 的倍数** ⇒ C 的行步长与块起点自洽。

### 5.4 AIV 侧的代价（**这是真正的风险点**）

`quant_matmul_relu_quant_vector(workspace, ..., m, n, rowStart, rows)` 现在按
**行连续 n 列**读；窗口主序下必须改成**读 c 段**（第 s 段宽 `windowN`、行步长 `windowN`、
块起点 `s*m*windowN`）。

* Pass-1（rowMax 累积）与 Pass-2（dequant + ReLU + 量化）都要改**取数**；
* **精度红线函数（`QmqQuantizeNearHalf` / `QmqDiv` / `QmqCorrectDiv`）不进不改**，
  只要喂给它们的值序列与顺序不变 ⇒ 逐字节等价；
* 行内的取数顺序改变**不影响结果**（rowMax 是 max，Pass-2 是逐元素），
  但**改变的是"每行的数据来自哪一段"** ⇒ 必须用穷举脚本验证每行的 c 段拼接后
  恰好覆盖 `[0, n)` 一次。

### 5.5 收益重算（用 §2.3 的正确占比）

`analysis/41` §3.2 的 S3 闭式：`墙钟_new = ceil(B·c/U)·(t16/c) + B·v16/(2U)`

| B | m 区间 | 最优 c | 墙钟_new（t16） | **增益** | 备注 |
|---|---|---|---|---|---|
| 6 | 81–96 | 4 | 0.25 + 0.0816 = **0.3316** | **4.00×** | 点 5、11 |
| 12 | 177–192 | 2 | 0.5 + 0.1633 = **0.6633** | **2.00×** | 点 7 |
| 4 | 49–64 | 6 | 0.1667 + 0.0544 = **0.2211** | **6.00×** | |
| 8 | 113–128 | 3 | 0.3333 + 0.1088 = **0.4421** | **3.00×** | |

⇒ 若点 5 打到 100 分、点 11 落到 ~41 分、点 7 落到 ~36 分，**仅这 3 个点就 ≈ +2.8 分**；
若 9 个 `m ≤ 384` 点平均都有 3~6×，**总分有望进入 25~30**。

**⇒ 这是唯一有可能到 25 分的路。** 但它是**大改**（动 vector 段取数），
必须等 v34 把 `AIV 占比` 测出来、且 `orgN` 假设被一次小实验证实之后再动。

### 5.6 便宜的"orgN 假设"验证（比 §5.3 小得多）

先只改 cube 的 `SetOrgShape(m, windowN, k, k)`（**AIV 完全不动**）：
* 若仍报 (c−1)/c ⇒ `orgN` 也不是 N 域的来源 ⇒ §5 整条关闭，回退 v20，另找出路；
* 若错误占比**变了**（例如变成"行内前 windowN 列对、其余错"）⇒ `orgN` 就是来源 ⇒ §5.3 可做。

**这一步等价于 v31 预登记表里"错误占比变化"那一支**，代价 1 次提交，收益是
**决定要不要投 ±2 周的大改**。
