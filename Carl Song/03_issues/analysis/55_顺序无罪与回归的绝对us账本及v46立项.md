## §三 ★★ 绝对 µs 账本 —— 四个候选全部出局

把 `v42 − v40 = +663.55 µs` 按**作用域**拆账（`ref/score_v45_live.py` 的 [5] 段）：

| 作用域 | 变化量 | 占回归 | 谁能解释 |
|---|---|---|---|
| **高组 6 点**（8/11/12/13/14/15，`N < 2048`） | **+624.61 µs** | **94.1%** | A / B1 / B2 —— 但三者已被独立否证 |
| **低组 6 点**（4/5/6/7/9/10，`N ≥ 2048`） | **+38.22 µs** | **5.8%** | C（**唯一**作用域） |
| 小点 1/2/3 | +0.72 µs | 0.1% | — |

> 分区来源是**测量**而非假设：v41 的扰动带门控 `currentN < 2048`，凡 Δ>0 的点必然 `currentN < 2048`
> ⇒ 高组 = 8/11/12/13/14/15（`analysis/49` §3）。

### 四条排除

| # | 候选 | 结论 | 依据（硬） |
|---|---|---|---|
| 1 | **A** 删行 999 恒等 `Maxs` | **无罪** | `v44 = v40 + A` 实测 **3690.41 µs**（全项目最低总耗时，落快簇上限） |
| 2 | **B1** `AllocTensor` 上移（纯重排） | **无罪** | `v45 = v40 + B1` 实测 **3706.57 µs**，落快簇 |
| 3 | **B2** 合并两个逐行标量循环 | **量级不可能** | 每核调用次数 ≤ 2、每次 `rows ≤ 8`（见 §四）⇒ 每核 ≤ 16 行的标量访问差 |
| 4 | **C** 取消 `ReduceMin` 预筛 | **被门控硬限制 ≤ 38.22 µs** | C 只在 `currentN ≥ 2048` 时改变行为，而该组的**全部**回归才 38.22 µs |

### ⇒ 定理

> **v42 的回归里，94.1% 的部分不能由 v42 相对 v40 的源码差异解释。**
> 因为：那一部分落在高组，而唯一能作用于高组的三个候选（A/B1/B2）分别被两条实测与一条结构性上界否证。

**这意味着两种可能，且只有两种：**

- **(P) 平台窗口**：v42/v43 的两次慢读数（4373.97 / 4381.50）本身不是源码属性。
  ★ 注意：E107 的「背靠背」证据其实**不是交错**的 —— v40 重测（3717.95）在前、v42 重测（4381.50）
  在 **15 分钟之后**，而 v42 之后**再没有测过 v40**。若平台在那一小时内漂移过，这条证据就解释不了差异。
- **(Q) 分区错**：即 `currentN ≥ 2048` 的实际点集与 E100 的高/低组分区**不一致**，
  于是 C 的真实作用域跨组 —— 那么本版（v46）正好是一次**免费形状探针**。

## §四 B2 的执行次数上界（源码证据）

`records/experiments/v40-tiny/kernel_v40_tiny.asc` 行 1067–1121：

```
const uint32_t blockM = static_cast<uint32_t>(tiling.singleCoreM);   // = tileM (4 / 16)
const uint32_t halfM  = (blockM + 1U) / 2U;
for (uint32_t localTile = 0; localTile < mBlocksPerGroup; ++localTile) {      // ≤ 2
    ...
    const uint32_t localRows = localEnd - localStart;                         // ≤ halfM ≤ 8
    for (uint32_t rowOffset = 0; rowOffset < localRows; rowOffset += kVectorTileRows) {  // 1 次
        const uint32_t currentRows = QmqMinValue(kVectorTileRows /*1024*/, localRows - rowOffset);
        quant_matmul_relu_quant_vector(..., localStart + rowOffset, currentRows);        // rows ≤ 8
    }
}
```

⇒ `quant_matmul_relu_quant_vector` 每核调用 **≤ 2** 次，每次 `rows ≤ 8`。
B 的两个行循环合计每核执行 **≤ 16 行**；B2「合并成 3 次标量访问」相对「4 次」的差是**每核十几条标量指令**。
在 600+ µs 的量级面前，这是 **10⁻⁴ 量级**。

★ **副产物**：这条也顺带把 `analysis/49/51` 里「Pass-2 行体每行 19 条指令被 N 摊薄」的模型**钉死了分母** ——
每核 Pass-2 行体执行次数 = `≤2 × ceil(n/6144) × rows`，其中 `rows ≤ 8`。
E100 的「每行固定开销」是**每行**的成本，行数上界 16 × nTiles。

## §五 v46 的设计与判读表

**v46 = v40 + C**（`records/experiments/v46-scanalways/`，sha **`1a7077c0224d4c96`**）
唯一改动：取消 `currentN >= 2048` 的 `ReduceMin` 预筛，`Compares` + 掩码扫描恒执行。
`livecode_diff(v40→v46)` 报**一处** `[replace]`：8 行 → 一个裸块 `{`；活代码净 **−7** 行。
九道 `selfcheck_all` **PASS**。等价性：预筛判定 ⟺「掩码非空」，掩码空的行在扫描体里
`while (bits != 0U)` 立即退出、一个元素都不改写 ⇒ 逐位相同（详见 SUBMIT §四）。

| 实测总耗时 | 判读 | 下一步 |
|---|---|---|
| **≈4360~4390 µs，位移集中在低组** | **C 有罪且机制成立** | ★ 转 **E110**：**高组没有预筛 ⇒ 高组每行无条件付这笔账** ⇒ 设计更便宜的「掩码为空」判据（`ReduceMin` 已被 v41 证否，须换载体：如对掩码做整块逻辑或再单次标量读） |

| **3900~4300 µs** | 不确定 | 立刻背靠背复测 v40 与 v45 |

### 为什么先测 C 而不是按 `analysis/54` 预告的「原版 v40 + B」

`analysis/54` §五 的分支 β 写的是「元凶 = 合并循环本身 ⇒ 下一步测原版 `v40 + B`」。本版**故意不**照做，理由：

1. **B2 的上界已经被结构性证据钉死**（§四）⇒ 测它得到「慢」的概率极低，且即便「慢」也无法解释量级；
   拿一次提交机会去测一个数学上不可能的东西，是浪费。
2. **C 的测试自带形状对照**：C 被门控在 `currentN ≥ 2048`，而 v42 的回归分布在高组。
   于是 v46 的结果**无论快慢都能同时回答 Q1（C 值多少）与 Q2（分区对不对）**。
3. 若判 C 无罪，我们一次性**关掉「找元凶」这条线**，把后续所有提交机会转回 E100 主线。

## §六 E109 副产物再次强化：**总分 ≠ 总耗时**（这次是排名反转）

| 版本 | 总分 | 总耗时 |
|---|---|---|
| v45 | **23.4080**（最高） | 3706.57 |
| v40 | 23.3818 | 3717.95 |
| v44 | 23.2295（最低） | **3690.41（最低）** |

v44 的**总耗时最低**却**总分最低**；v45 的**总分最高**却**总耗时不是最低**。
原因同 `analysis/54` §五：`ΔS = 2.4663e-4·S²` 而 `dS/dt ∝ S²/t` —— 收益落在**大点**时总分涨得慢，
落在**小点**时总分涨得快。v44 的快是点 11~15 换来的（对总分不敏感），v45 的快包含点 2/3/14 的改进。

⇒ **判收益只能看「逐点 × 边际价值」，`总耗时` 只是一个中间量。**（E109 副产物，第二次实证。）

## §七 两支各自的下一步（都已备好）

### 若判 **C 有罪** ⇒ 立 **E110：掩码扫描的代价是「每行 × N/64 次标量读」**

Pass-2 行体里那段

```
for (uint32_t maskGroup = 0; maskGroup < compareCount / 64U; ++maskGroup) {
    uint64_t bits = candidateMask.GetValue(maskGroup);   // ← UB 标量读
    while (bits != 0U) { ... }
}
```

的迭代次数 = `ceil(currentN/64)`，**与 N 成正比、与行数相乘**，且**在 `currentN < 2048`（高组）时
是无条件的**（v40 把预筛只加在了 `currentN ≥ 2048` 一侧）。
v41 曾试图把 `ReduceMin` 预筛扩到高组 ⇒ **净损失**（E101）⇒ 说明「用一次 `ReduceMin` 换掉这段扫描」
在高组不划算。**E110 的方向：换一个更便宜的「掩码为空」判据**（对掩码自身做整块逻辑或 + 单次标量读），
使高组也能省掉这段扫描。

### 若判 **C 无罪** ⇒ 撤回「真实回归」，重测 v42

- **第三次 v42 原样重测**（同 sha）+ 紧接一次 v40（形成 A→B→A 交错）。
- 若 v42 这次进快簇 ⇒ 把 `analysis/50/51/52` 的「档位漂移」表述**重新启用**，
  并把 **E106 升级为「跨提交比较必须交错，不能只背靠背」**；
  同时 `analysis/53` §一 的「(Q) 真实回归坐实」要**逐条撤回**（这会是一次公开的二次自我纠错）。
- 之后全部提交机会转回 **E100 主线**：高组 6 点的「每行固定开销」，攻击面按 §四的钉死结果重算。
