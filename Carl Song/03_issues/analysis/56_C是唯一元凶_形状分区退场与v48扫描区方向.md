## §二 ★★ 慢簇三版全部含 C ⇒ 平台档位出局

这是本轮最省事、也最重要的一步。读 `records/experiments/v43-barriercut/v43_vs_v40.diff`
第 174~184 行：

```diff
-                bool hasNearHalf = true;
-                if (currentN >= 2048U) {
-                    LocalTensor<float> scalarMinLocal = scalarMaxBuffer.Get<float>();
-                    ReduceMin(scalarMinLocal, residualLocal, scratchLocal, alignedN);
-                    PipeBarrier<PIPE_V>();
-                    hasNearHalf = !(scalarMinLocal.GetValue(0) >= kHalfScreenTolerance);
```

**v43 的 diff 把 C 整块当成"删除行"** ⇒ v43 的基线是 **v42**，不是 v40 ⇒ **v43 ⊇ C**。

于是：

| 档位 | 版本 | 是否含 C |
|---|---|---|
| 快簇（8 读数）| v35 / v38 / v39 / v40×2 / v41 / v44 / v45 | **全部不含 C** |
| 慢簇（4 读数）| v42 / v43 / v46 | **全部含 C** |

> ★ **完美的一一对应 ⇒ 「平台档位漂移」（E110 的 (P) 分支）彻底出局。**
> 档位是 C 的**代码属性**，不是平台的瞬态，也不是「同一 sha 重测就变」。
>
> ★ 同时修掉一处历史误记：`analysis/50/51/52` 曾把 v42/v43 的慢归因于平台档位；
> `analysis/53` 已撤回该说法，本文件补上**唯一正确的归因对象 = C**。
>
> ★ 副产物：**v43「删 16 条 barrier = 零收益」这个结论的方向要重写** ——
> 它不是"零收益"，而是「**v43（含 C）相对 v42（含 C）只快 0.17%**」，
> 也就是「在 C 已经 +18% 的地基上，再删 16 条 barrier 也几乎不动」。
> 结论不变（barrier 方向关闭），但**理由变了**。

## §四 ★★ E113（本轮新立）：形状分区不能解释 C —— 逐点回归是一条连续谱

E100 的旧分区是 `currentN < 2048 = {8,11,12,13,14,15}`（高组）／
`currentN >= 2048 = {4,5,6,7,9,10}`（低组）。若 C 只作用于 `currentN >= 2048`，
那么 C 的代价应当**只落在低组**（上界 38.22 µs）。但实测：

- 旧 HI 组相对回归 = `{2.73, 8.92, 15.13, 19.50, 20.71, 22.60}`
- 旧 LO 组相对回归 = `{2.22, 3.22, 6.66, 6.77, 15.06, 18.56}`

**两组内部都横跨 2%~23%，没有任何阈值能切开 ⇒ 分区不是 C 的解释变量。**

- 但按 **`t − O`（剥掉 `O ≈ 10.5 µs` 固定开销）归一**后，大点收敛到 **+9%~+23%**、
  小点归入噪声 ⇒ **C 的代价 ≈ 对"工作量"施加一个与形状无关的 +18~20%。**
- 交叉核对 v41 的扰动（把预筛改成无条件）：对 {8,11,12,13,14,15} 是**变慢**
  （点 8 +11.81 µs、点 14 +12.35、点 15 +40）⇒ 那 6 点确实是 `currentN < 2048`
  （新拿到预筛）；但 v41 的总代价只有 +1.65%（3779.29）—— 与 C 的 +20% 量级差一个数量级。
  ⇒ **「加预筛」与「删预筛」对同一段代码的代价严重不对称** ⇒ 不是线性成本模型。

> ★ **E113 结论**：不要再拿「形状分区」去解释 Pass-2 扫描区的代价。
> 该区的代价是**对整块代码的扰动敏感度**问题（见 §五），不是"哪些点走哪条分支"的问题。
> 「形状分区」仍可用于**定位**（哪些点会被某条门控命中），但不能用于**定量归因**。

## §五 ★★ E112（本轮新立）：Pass-2 掩码扫描区是「微扰危险区」

把该区的四次扰动并排看：

| 版本 | 对该区做了什么 | 结果 |
|---|---|---|
| v41 | 把 `if (currentN >= 2048)` 改成无条件预筛 | 慢簇的**外**，但该区覆盖的点 8/14/15 分别 +10.7%/+1.6%/+2.5% ⇒ 总 +1.65% |
| v42 | 删预筛（C）+ 行体两处（A/B）| **+17.85%（慢簇）**|
| v43 | 在 v42 之上再删 16 条 barrier（含该区那条）| **+17.61%（慢簇）**|
| v46 | 只删预筛（C）| **+20.13%（慢簇）**|

⇒ **四次扰动，四次都变慢；其中三次跨过 +17% 的悬崖。**
⇒ **E112：该区（`Abs(residualLocal)` 之后到 `PipeBarrier<PIPE_V>()` 之前的
「预筛 + `Compares` + 字扫描」整块）不要做"删一行/加一行"式的微扰。**

机制候选（未验证，仅供设计参考）：
1. **编译器调度悬崖**：`ReduceMin` + 分支 + `Compares` + `while` 标量循环混在一块，
   删掉其中一条会把编译器的软件流水线/标量-向量重叠方案整体换掉 ⇒ 阶跃而非线性。
   （与 E105 的「删 16 条 barrier = 0 收益」、E108 的「行体代价不由指令条数决定」互洽。）
2. **同步替换**：手工 `PipeBarrier<PIPE_V>` 被删后，编译器为保证正确性插入更保守的同步
   （`PIPE_ALL` 级），代价远高于手工那条。
3. **标量流水线气泡**：`ReduceMin` 之后的 `GetValue(0)` 是一个"向量→标量"的强制栅栏点；
   删掉它会把后续 `Compares` 的发射窗口前移，破坏重叠。

> ★ **可操作规则（本轮采纳）**：**要动该区，就整块重构**（换成结构上不同的实现，
> 并自带形状对照），**不要做微扰**。这与「删 barrier」方向（E105，已关闭）是同一条教训。

## §六 ★ 扫描区的经济学与 v48 方向

### 6.1 该区到底在干什么（读源码的结论）

```
Cast(fp32Local, inputLocal, CAST_RINT) → Muls → Mul → Maxs(ReLU)        // 行体 4 条
if (rowMaxPrefetch[row] > 0)
    DataCopy(activationLocal, fp32Local)
    Duplicate(negScaleLocal, scaleValue)
    QmqDiv(fp32Local, activationLocal, negScaleLocal)                   // 精确除法
    Cast(floorLocal, fp32Local, CAST_FLOOR)
    Cast(residualLocal, floorLocal, CAST_NONE)
    Adds(residualLocal, +0.5) ; Sub ; Abs → residual = |q − (floor(q)+0.5)|
    ── 预筛（仅 currentN >= 2048）──
    ReduceMin(minLocal, residualLocal) ; hasNearHalf = !(min >= 2e-05)
    ── 扫描（hasNearHalf 时）──
    Compares(mask, residualLocal, 2e-05, CMPMODE::LT, compareCount)
    for (maskGroup = 0; maskGroup < compareCount/64; ++maskGroup)      // ★ 无条件走完
        bits = candidateMask.GetValue(maskGroup)                       // ★ UB 标量读
        while (bits) { lane = GetSFFValue<1>(bits); ... QmqQuantizeNearHalf ... }
```

- **字扫描是无条件走完 `⌈compareCount/64⌉` 个字的**，即使一个字都没置位。
  ⇒ 每行固定付 `⌈N/64⌉` 次 UB 标量读 + 循环控制。N=2048 时是 **32 次**；
  N<2048 时 ≤ 32 次。
- `QmqQuantizeNearHalf`（精度红线，v40 行 222~288）是**用整数尾数比较精确复现
  `rint` 的 tie-breaking**：先把 `approximate` 与 `floor+0.5` 的**位模式距离**
  限制在 `<= 2 ULP`（`distance > 2U ⇒ return -1`），再按偶/奇整数选
  `above` / `above || equal`。**它的判据比 `Compares` 的 2e-05 严了约 1000 倍**
  ⇒ 掩码是"粗筛"，真正的候选项极少。
- ⇒ **把 `QmqQuantizeNearHalf` 向量化是不可行的**：它需要 64 位尾数移位比较，
  向量化要 10 条以上向量指令并且每行都付，反而更贵；且它是精度红线（一个字不能改）。

### 6.2 结论：唯一杠杆 = **让"掩码为空"这件事被测得足够便宜**

- 掩码空 ⇒ 应跳过字扫描（v40 在 `currentN >= 2048` 时靠 `ReduceMin` 做到了，
  且这正是 C 移除后暴涨 +20% 的原因 ⇒ **"跳过"这件事值 ~18~20% 的工作时间**）。
- `currentN < 2048` 的点**没有这个跳过机制**，无条件走完字扫描 ⇒ E111 成立。
- v41 用「整行 `ReduceMin`」补这个机制 ⇒ 反而变慢
  （`ReduceMin` 的成本 > 短扫描的节省，`currentN < 2048` 时 `⌈N/64⌉ ≤ 32`）。
  ⇒ **需要一个比 `ReduceMin(4N 字节)` 便宜得多的判空。**

### 6.3 v48 候选（按推荐度）

| 代号 | 做法 | 数据量 | 新 API 风险 | 备注 |
|---|---|---|---|---|
| **S1（推荐）** | **8:1 `Min` 折叠 + `ReduceMin`**：先用 7 条 `Min` 把 `residualLocal` 折成 `n/8` 长，再 `ReduceMin` 到 1 个标量 | **1/8** | 无（`Min`/`ReduceMin` 都是标准算子）| 折叠本身只花 ~0.875n 元素操作（相对行体 19n 可忽略）|
| S2 | 掩码整块判空：`Compares` 后对掩码字节视图 `ReduceMax`，非空才走字扫描 | **1/32**（`N/8` 字节）| **有**（`ReduceMax` 对 `uint8`/`uint16` 的支持未验证）| 收益更大但可能编不过 |
| S3 | 收紧 `Compares` 阈值（2e-05 → 1e-06）| 0（不减少字扫描）| 无 | **不能解决字扫描**，只减少候选项 ⇒ 无效 |
| S4 | 把「预筛 + 扫描」整块换成「`Mins` 掩码化 + `Select` 向量化修正」| — | 极高 | 触碰精度红线 ⇒ **不可行** |

**S1 的形态（自带低组对照，E86）**：

```cpp
// [OPT-V48] 把预筛的判据数据量降到 1/8：先把 residual 8:1 折叠，再归约。
//          currentN >= 2048 走这条（替代原 ReduceMin）；currentN < 2048 也走这条
//          （把 v40 的"无条件扫描"升级为"廉价判空 + 条件扫描"）。
//          等价性：min(residual) >= tol  ⇔  min(fold(residual)) >= tol（Min 是结合律运算）。
LocalTensor<float> foldLocal = scratchFoldBuffer.Get<float>();
const uint32_t foldCount = QmqCeilDiv(alignedN, 8U);          // 向上取整
Duplicate(foldLocal, residualLocal, foldCount);               // 首段直接拷贝
for (uint32_t k = 1U; k < 8U; ++k) {
    const uint32_t off = k * foldCount;
    if (off < alignedN) {
        Min(foldLocal, foldLocal, residualLocal[off], QmqMinValue(foldCount, alignedN - off));
    }
}
ReduceMin(foldLocal, foldLocal, scratchLocal, foldCount);      // 数据量 = n/8
```

> ⚠ 未验证项：`LocalTensor::operator[]` 的切片语义、`Duplicate` 的 src 为 `LocalTensor`
> 重载、`Min`（三目 `LocalTensor` 版本）的存在性、尾部 count 不足 32B 时的处理。
> 这些都要在真机上第一次编译才知道 ⇒ **S1 应当作为 v48 的独立一次提交（不与 v47 合并）**。
